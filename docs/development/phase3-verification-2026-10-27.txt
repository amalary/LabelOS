LabelOS Phase 3 implementation gap report
Verified October 27, 2026 (America/Los_Angeles)

Decision: stop for approval. The governance foundation and provider adapters are
present, but the A&R product workflow is incomplete. Fix the onboarding ownership
authorization gap before treating local onboarding as ready.

Baseline: HEAD a15bca5, plus the existing uncommitted YouTube research API work.
The five previously modified files and six previously untracked files were
preserved. No application feature, migration, or existing environment file was
changed. This report and ignored verification artifacts are the only additions.

Current capabilities

- Implemented: workspace source registry; datasets and immutable versions;
  datasheet review/eligibility; collection lifecycle, retries and checkpoints;
  dataset and record lineage; activity/outbox composition; persisted governance
  capability checks and workspace isolation. Artist/profile CRUD and Analytics
  observations/series exist as adjacent foundations.
- Implemented: typed provider contracts, normalized records, provenance/expiry,
  credential references, cancellation/deadlines, sanitized errors, bounded pages,
  fixed-origin GET transports and optional provider search fan-out.
- Partial: YouTube has authenticated search, lookup and observations routes in the
  uncommitted tree. They require governance.manage and a running YouTube collection,
  enforce workspace/run binding and production documentation eligibility, and
  return display-only data. They do not persist observations, checkpoint or finish
  collection runs. Only the shared local secret reference is configured; no
  workspace-specific YouTube credential bindings exist locally.
- Partial: MusicBrainz, SoundCloud, Last.fm, Songkick and Wikidata have narrower
  adapter capabilities and access gates, without research HTTP/UI integration.
  Spotify is deliberately disabled in the current implementation. This review
  confirms code behavior, not a fresh legal/provider-policy assessment.
- Absent: research/governance frontend pages and proxy routes; durable scouting
  shortlists, evaluation/scoring and signing workflows; automatic artist identity
  resolution; governed ingestion worker and delivery deduplication; distributed
  project quota budgets; retention/deletion execution and abandoned-run recovery.
  The scouting agent is deterministic mock output. Generic lineage primitives do
  not implement an artist-resolution workflow. Current YouTube contracts explicitly
  restrict returned counters to display, so they are not a scoring input.

Blocking finding: onboarding can grant ownership to an existing guest

apps/api/src/labelos_api/api/v1/onboarding.py only rejects a conflicting non-null
principal organization ID. For a matching organization, it assigns owner_user_id
to the caller and sets their membership permission/role to owner, accepting the
submitted membership status without verifying WorkOS owner authority.

A disposable in-memory SQLite HTTP probe with a mocked authenticated guest in the
same workspace returned 200 and persisted both organization ownership and owner
membership for that guest. No live account or development database was modified.
The existing focused suites do not prevent this behavior. Reproduction artifact:
.tmp/phase3_onboarding_probe_20261027.py. Fix and add a negative authorization
regression check only after approval.

Test harness finding

The first focused run tried to disable PostgreSQL with an empty TEST_POSTGRES_URL
in a child process. Windows dropped that empty variable, allowing conftest.py to
reload .env.test.local (127.0.0.1:55438/labelos_test). Connections were refused before
schema creation. That run was stopped. The replacement runner executes pytest in
process, preserves the explicit empty value, and blocks asyncpg connections.
All database mutations in the completed verification use disposable SQLite.
Do not reuse the default PostgreSQL fixtures without verifying a disposable target.
